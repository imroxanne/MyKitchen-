# Архитектура и выбор стека (A1)

Решение принято 2026-10-28. Требования из ТЗ, влияющие на выбор: бесплатно без
неожиданных списаний, телефон + десктоп, личные данные и синхронизация между
устройствами (E1), раздельные приватные профили близких, основная логика без
платного ИИ, в будущем — импорт рецептов по ссылке (C3).

## Стек

| Слой                | Выбор                                                                     | Почему                                                                                                                                                                                                     |
| ------------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Интерфейс           | **React 19 + TypeScript + Vite**, React Router 7 (SPA)                    | Приложение закрытое (SEO не нужно), SPA проще и дешевле в хостинге, чем SSR. TypeScript ловит ошибки в расчётах КБЖУ и модели данных.                                                                      |
| БД, вход, хранилище | **Supabase** (Postgres + Auth + Storage), план Free                       | Реляционная модель подходит для рецептов/ингредиентов/единиц; Auth и RLS дают приватность данных по пользователю без своего сервера; миграции — SQL-файлы в репозитории.                                   |
| Хостинг             | **Vercel Hobby**                                                          | Бесплатно для некоммерческого личного использования, сборка из GitHub, превью-сборки для веток. На Hobby нет платы за превышение — при исчерпании лимитов сайт приостанавливается, а не выставляется счёт. |
| Серверная логика    | Пока нет. Позже — Supabase Edge Functions или функции Vercel              | Нужна только для импорта по ссылке (C3) и подобного; добавляется, когда понадобится.                                                                                                                       |
| Тесты               | Vitest + Testing Library (юнит), Playwright (сквозные, телефон и десктоп) | Проверка сценариев целиком, как требует дорожная карта.                                                                                                                                                    |
| Качество            | oxlint, Prettier, `tsc`                                                   | Быстрые проверки, запускаются в CI на каждый push.                                                                                                                                                         |
| CI                  | GitHub Actions                                                            | Для публичного репозитория бесплатно; поднимает чистый Postgres и применяет миграции с нуля.                                                                                                               |

### Рассмотренные альтернативы

- **Next.js (SSR)** — избыточно: нет публичных страниц, SSR усложняет хостинг и приватность.
- **Firebase** — NoSQL хуже подходит для связей рецепт↔ингредиент↔единица и агрегатов (КБЖУ, список покупок); Postgres даёт ограничения целостности.
- **Только localStorage / PWA без сервера** — не выполняет синхронизацию устройств и раздельные профили (ТЗ §12).
- **Cloudflare Pages + D1** — хороший бесплатный вариант, но коннектор Cloudflare не авторизован в этой среде, а аккаунты Supabase и Vercel у владелицы уже есть.

## Бесплатные лимиты и риски

Проверено 2026-10-28; аккаунт Supabase — план **Free**, Vercel — команда «Roxanne's projects».
Цифры из сторонних обзоров расходятся, точные значения сверять на supabase.com/pricing и vercel.com/pricing.

| Риск                                                                   | Мера                                                                                                                                                                                                                                                                                                                                                                        |

## Структура репозитория

```
src/
  app/        оболочка: маршруты, навигация, список разделов
  pages/      экраны (пока заглушки разделов и экран состояния /status)
  lib/        конфигурация окружения, клиент Supabase, проверка БД
  test/       настройка юнит-тестов
e2e/          сквозные тесты Playwright
supabase/
  config.toml локальный стек Supabase
  migrations/ SQL-миграции (единственный способ менять схему)
docs/         ТЗ, дорожная карта, архитектура, окружения, карта данных, статус
.github/workflows/  CI и keep-alive
```

Будущие функции добавляются модулями `src/features/<раздел>/` (компоненты, запросы к БД,
чистая логика с юнит-тестами — например, расчёт КБЖУ отдельно от интерфейса).
