## A5 — подбор по продуктам и базовые фильтры (2026-10-29)

Критерий: выдача корректно учитывает отсутствующие ключевые ингредиенты; фильтры совмещаются.

**Правила подбора** (`src/features/matching/match.ts`):

- значимость ингредиента: основа блюда (вес 10) > основной (3) > второстепенный (1); «по желанию» и
  «по вкусу» не влияют на подбор, но показываются; вода считается доступной всегда;
- продукт с пометкой «не учитывать» считается отсутствующим; «Мясо (любое)» подходит при любом
  продукте категории «Мясо и птица»;
- количество: сравнивается только в сопоставимых единицах (г/кг, мл/л/ложки/стакан, одинаковые штучные);
  не хватает — «мало» (нужно докупить); количество неизвестно или несравнимо — «есть, количество не
  сравнивалось» (не считается подтверждённым);
- порядок: сначала без недостающей основы блюда, затем по весу недостающего, числу покупок, числу
  несравненных количеств, доле имеющегося, времени.

**Сделано.**

- Режимы из ТЗ: «Из имеющегося», «Докупить не больше N» (1–5), «Без учёта запасов» (по умолчанию,
  если запасы пусты — с подсказкой добавить продукты).
- Фильтры: поиск по названию и ингредиентам (все слова), время (до 15/30/60/120 мин — рецепты без
  указанного времени скрываются с пометкой, сколько скрыто), тип блюда, «только с проверенным
  источником», сортировка «по подходящим / сначала быстрые», «Сбросить фильтры». Всё — в адресе страницы.
- Карточка: «есть X из Y», «Все нужные продукты есть» / «Не хватает: …, — основа блюда», «Количество не
  сравнивалось: …», «Готовится за N мин».
- Страница рецепта: отметки «есть / мало / нет / есть, количество не сравнивалось» и строка «Не хватает».
- Найдено и исправлено: проверка типов не охватывала тестовые файлы (с A3).

**Проверено.**

- Юнит-тесты логики (13) с проверкой мутациями: если отключить режим «из имеющегося» или учёт
  значимости, тесты падают; тесты экранов (режимы, совмещение фильтров, адрес, пустое состояние,
  отметки на странице рецепта).
- e2e на Supabase с реальными рецептами: продукты для шакшуки без масла → в «из имеющегося» её нет,
  в «докупить не больше 1» — «Не хватает: Масло оливковое»; поиск + «Десерт» → пусто; добавили масло →
  шакшука в «из имеющегося», на странице рецепта — «все нужные продукты есть».
- Вёрстка на телефоне: первый рецепт виден на первом экране, без горизонтальной прокрутки.

**Известные ограничения.**

- Количества в рецептах указаны на всё блюдо; пересчёт на другое число порций — B2.
- Альтернативы вида «или говядина» в примечаниях не учитываются при подборе (замены — B5).

## A4 — начальная база рецептов (2026-10-29)

Критерий: можно открыть полный рецепт и перейти к оригиналу; непроверенные рецепты честно обозначены.

**Источник и права.** «Книга рецептов» русского Викиучебника (ru.wikibooks.org), лицензия CC BY-SA 4.0.
У каждого рецепта: ссылка на страницу, номер версии страницы, ссылка на историю правок (авторы),
лицензия, что изменено (выбранный вариант, шаги пересказаны, особенности источника). Если страница
приводит рецепт по книге (КВЗП 1952, «Кулинария» 1955 и др.) — это указано. Фото не используются.

**Сделано.**

- 22 рецепта (`content/recipes/batch-01`): шакшука, сырники, блины, шарлотка, банановый хлеб, брауни,
  картофельное пюре, тефтели, голубцы, гречневая каша, бефстроганов, гороховый и луковый супы,
  макароны по-флотски, шведские фрикадельки, оливье, вальдорфский салат, нисуаз, драники, оладьи,
  плов, винегрет.
- Ничего не выдумано: диапазоны и «по вкусу» оставлены текстом, отсутствующее время/порции — пусто,
  нестандартные места источника перечислены в «Изменениях».
- 21 рецепт сверен с версией страницы («Источник и полнота проверены»); винегрет — нет: в источнике
  шаги и состав не совпадают, это показано на странице рецепта. «Проверен приготовлением» — ни у одного.
- Справочник продуктов дополнен 16 позициями (`scripts/catalog/ingredients-2.tsv`).
- База: лицензия, авторы, версия страницы, пометка об адаптации; запрет публикации без установленных прав.
- Экраны: «Что приготовить» — список (вся карточка ведёт в рецепт); страница рецепта — статусы с
  пояснениями, время, порции, ингредиенты, шаги, источник, лицензия, «Открыть оригинал».

**Проверено.**

- Генератор: каждый продукт есть в справочнике, единицы допустимы, нет количества без единицы,
  указаны лицензия и авторы; эвристическая сверка — все числа рецептов встречаются в тексте источника.
- База: миграции с нуля, 22 рецепта, число ингредиентов/шагов совпадает с файлами;
  SQL `a4_recipes.sql` (лицензии, запрет публикации без прав, нет «проверен приготовлением»).
- Юнит-тесты экранов и логики; сквозной тест в CI на Supabase: список → рецепт → оригинал/статусы →
  назад, винегрет помечен «Источник не проверен».
- Облако: три миграции применены (лицензии, дополнение справочника, партия рецептов); контрольные
  хеши всех 22 рецептов (поля, ингредиенты, шаги, источник) совпадают с базой, собранной из файлов;
  анонимный доступ к рецептам и продуктам отклоняется.

**Известные ограничения.**

- Советник Supabase рекомендует включить защиту от утёкших паролей (проверка по HaveIBeenPwned) —
  это настройка входа в панели Supabase; разберём в E3 (защита учётных записей).
- Шаги многих рецептов — по советским сборникам: формулировки и времена (например, упревание каши
  3–4 часа) сохранены как в источнике, а не «осовременены».

## A3 — справочник продуктов и запасы (2026-10-29)

Критерий: пользователь сохраняет продукты, редактирует их и после перезапуска видит тот же список.

**Сделано.**

- Общий справочник: 226 продуктов в 17 категориях, 198 синонимов («помидор» → Томат, «буряк» → Свёкла).
  Исходник — `scripts/catalog/ingredients.tsv`, миграция генерируется и проверяется на дубли;
  числовых пищевых данных в справочнике нет (A7/B1).
- Вход по email и паролю (Supabase Auth); сессия хранится в браузере, данные — в аккаунте.
- «Мои продукты»: поиск по названиям и синонимам без учёта регистра, ё и окончаний; выбор нескольких
  продуктов за раз; просмотр по категориям; свой продукт (виден только владельцу); группы
  «Сейчас есть» / «Обычно есть»; количество + единица (или «не указано» — не считается достаточным),
  срок годности с пометкой «скоро»/«просрочено»; перенос между группами; «не учитывать при подборе»;
  удаление с подтверждением; понятные ошибки с повтором без потери ввода.
- Профиль: email аккаунта и выход.

**Проверено.**

- Юнит-тесты (30): поиск, разбор количества, сроки, генератор справочника, полный сценарий экрана
  (добавление, правка, перенос, удаление, «перезапуск», ошибки сети).
- SQL: `a3_catalog.sql` — справочник, синонимы, сохранение и правка продукта пользователем.
- Сквозной тест на настоящем Supabase в CI (телефон и десктоп): регистрация → добавление по
  синонимам → количество/единица/срок → перенос → свой продукт → перезагрузка страницы → вход с
  «другого устройства» → тот же список; второй пользователь не видит чужие продукты; выход.
- Облако: миграция справочника применена (226 продуктов, 198 синонимов).

**Известные ограничения.**

- Письмо подтверждения регистрации: после перехода по ссылке Supabase перенаправляет на «Site URL»
  проекта; пока он не настроен на адрес сайта, откроется пустая страница — аккаунт при этом
  подтверждён, нужно вернуться на сайт и войти.
- Встроенная почта Supabase Free отправляет лишь несколько писем в час — достаточно для личного использования.

## A2 — модель данных (2026-10-29)

Критерий: схемы/миграции работают; данные можно создать, прочитать и обновить без нарушения связей.

**Сделано.** Миграция `supabase/migrations/*_data_model.sql`:

- `units` (г, кг, мл, л, ложки, стакан — с пометкой «ориентировочно», шт., зубчик, пучок, упаковка,
  щепотка, по вкусу), `ingredient_categories` (17 категорий);
- `ingredients` с нормализованным названием (регистр, ё→е, пробелы), общий справочник и личные
  продукты пользователя, `ingredient_synonyms`;
- `user_products`: «обычно есть» / «сейчас есть», количество и единица только вместе
  (неизвестный остаток — пусто, а не ноль), срок годности, «не учитывать»;
- `recipe_sources` (ссылка, автор, дата, права использования), `recipes` с раздельными статусами
  «проверены источник и полнота» и «проверен приготовлением» (только с пояснением), признак тестовых
  данных, `recipe_ingredients` (значимость: ключевой/основной/второстепенный/по желанию), `recipe_steps`;
- RLS на всех таблицах: справочники читают вошедшие, свои продукты видит и меняет только владелец,
  рецепты пока создаёт только администратор (пользовательские — в C2 с модерацией), `anon` без доступа.

**Проверено.**

- `supabase/tests/a2_data_model.sql`: создание/чтение/обновление, запрет нарушений связей
  (удаление используемого продукта, количество без единицы, статус без основания, внешний рецепт без
  источника), каскады при удалении, изоляция двух пользователей, запрет записи в справочник.
  Проходит на обычном Postgres (`npm run db:test:shim`) и в CI на настоящем Supabase.
  Проверено, что тест падает, если ослабить политику доступа.
- Облако: миграция применена, советник безопасности Supabase замечаний не нашёл.

## A1 — основа проекта с нуля (2026-10-28)

Критерий: проект запускается локально; создан начальный интерфейс; настроен Git.

**Исходное состояние.** Репозиторий содержал только `README.md`; прототипа нет — проект
создаётся с нуля (дорожная карта обновлена с учётом этого).

**Сделано.**

- Стек выбран и обоснован (docs/ARCHITECTURE.md): React + TypeScript + Vite, Supabase Free, Vercel Hobby.
- Начальный интерфейс: оболочка с навигацией по шести разделам ТЗ (телефон — нижняя панель,
  десктоп — верхняя), разделы честно помечены как нереализованные с указанием пунктов,
  экран `/status` с проверкой связи с БД.
- Git: ветка `a1-foundation`, осмысленные коммиты, `.gitignore` для секретов (`.env.*`).
- Supabase: облачный проект `mykitchen`, локальная конфигурация `supabase/`, миграция `app_health()`.
- Vercel: проект `mykitchen`, переменные окружения Production/Preview, SPA-перенаправления;
  сборки из GitHub работают.
- CI (GitHub Actions): lint, типы, юнит-тесты, сборка, Playwright (телефон + десктоп),
  применение миграций к чистому Postgres. Keep-alive для бесплатного Supabase.
- Документы: ARCHITECTURE, ENVIRONMENTS, DATA_MAP, CLAUDE.md для следующих сессий.

**Проверено.**

- Локально: `npm run check` — lint, типы, 10 юнит-тестов, сборка, 6 e2e-тестов (телефон и десктоп) проходят;
  `npm run dev` поднимает приложение.
- Облачная БД: миграция применена, `app_health()` вызывается от роли `anon`, советник безопасности Supabase замечаний не нашёл.
- GitHub Actions: оба задания CI зелёные (приложение; миграции на чистом Postgres + `app_health()` от `anon`).
- Vercel: сборка ветки в состоянии READY, прямой адрес `/pantry` отдаёт приложение, адрес и ключ Supabase попали в сборку.

**Известные ограничения.**

- Сборка ~530 КБ JS (большая часть — supabase-js); разделение кода — в E4.
- Сайт закрыт Vercel Authentication (виден только владелице после входа в Vercel).
  Собственного входа в приложение пока нет — E1.
- Регистрация в Supabase Auth открыта по умолчанию — закрыть при включении входа (E1).
- Из среды разработки ИИ нет сетевого доступа к `*.supabase.co` и `*.vercel.app`, поэтому
  связка «браузер на сайте → БД» проверяется открытием `/status` на сайте.
