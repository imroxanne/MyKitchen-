# Карта сохраняемых и временных данных

Цель — чтобы было ясно, где живёт каждая категория данных, что переживает
перезапуск/смену устройства, что приватно и что является тестовым.

## Классы хранения

| Класс                  | Где                           | Переживает перезагрузку | Между устройствами | Примечание                                               |
| ---------------------- | ----------------------------- | ----------------------- | ------------------ | -------------------------------------------------------- |
| **S — сервер**         | Supabase Postgres (+ Storage) | да                      | да                 | Источник истины. Доступ по строкам через RLS.            |
| **L — устройство**     | `localStorage` браузера       | да, но может очиститься | нет                | Только удобства: черновик ввода, последний фильтр.       |
| **U — адрес страницы** | URL (путь и параметры)        | да (ссылкой)            | по ссылке          | Текущий поиск/фильтры, чтобы «назад» и ссылка работали.  |
| **M — память**         | состояние React               | нет                     | нет                | Открытые панели, ввод до сохранения.                     |
| **G — Git**            | репозиторий                   | да                      | да                 | Код, миграции, справочные/тестовые данные. **Публичен.** |

## Что реализовано сейчас (после A2)

| ----------------------------- | ----- | --------------------------------------------------------------------------------------------- |
| Функция `public.app_health()` | S     | Служебная, без данных. Используется `/status` и keep-alive.                                   |
| Текущий раздел                | U     | Маршруты `/`, `/pantry`, `/favorites`, `/diary`, `/plan`, `/profile`, `/status`.              |

## Правила

1. Источник истины — сервер. `localStorage` только для удобств; его потеря не теряет данные.
2. В Git (публичный!) не попадают личные данные, секреты и чужой контент без прав.
3. Тестовые и демонстрационные данные помечаются явно (поле/флаг `is_sample` или префикс
   источника) и не выдаются за проверенные рецепты, реальные цены или точное КБЖУ.
4. История (дневник) хранит снимки, а не ссылки на изменяемые рецепты.
5. Каждая пользовательская таблица имеет `user_id` и политики RLS; без RLS таблица не создаётся.
